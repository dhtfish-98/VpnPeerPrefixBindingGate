# Hosted kernel run 37407758390: failure and bounded diagnosis

The [public GitHub Actions run](https://github.com/dhtfish-98/VpnPeerPrefixBindingGate/actions/runs/37407758390) on `main` commit `625c4568d73346ac44f8703d5bb1835060375de9` completed its `build-and-test` job successfully. Its `real-kernel` job failed at `namespace_run` on Ubuntu 24.04 image `20260927.320.1`, kernel `6.17.0-1022-azure` (x86_64). The downloaded [machine receipt artifact](https://github.com/dhtfish-98/VpnPeerPrefixBindingGate/actions/runs/37407758390/artifacts/11387930777) is `TEST_FAIL`, not a hosted PASS. The artifact ZIP SHA-256 is `75feeabeff4de3ac84a263ba6a828347f9773447e82600f8ce75308dbd2544b1`, matching the GitHub API digest; the extracted JSON SHA-256 is `9d3ee260dd1c105159e1218e84b4579d516977eec8266447dfa56c4163465fb5`.

The receipt reports a zero exit code from the guest experiment, real WireGuard's four expected deliveries, an identical encrypted replay result, all six expected guard decisions, and the weak gateway's forwarding event. It reports only four receiver delivery lines instead of nine: the weak and guarded synthetic TUN receivers each exited without their expected deliveries. The raw runner log was intentionally not uploaded and cannot now be inspected, so this receipt alone does not prove a particular runner sysctl value.

To test the likely mechanism, the same pinned Alpine Linux VM fixture was rerun with strict `rp_filter=1` in its isolated network namespace before the synthetic stages. It reproduced the hosted receipt's observable pattern: four WireGuard deliveries, six guard decisions, weak forwarding, and zero deliveries to the weak/guard receivers (`VM_RESULT=FAIL`). Its 5,395-byte serial log SHA-256 is `3f7692ecff29d0293a97496f121308fa12f4a0ac88c0695716b39c207c93cbb2`. The source revision then explicitly sets `rp_filter=0` for the isolated synthetic TUN experiment, reads back `all`, `default`, `weak0`, and `guard0`, and requires two marker lines. A rebuilt pinned VM on that revision produced all nine receiver deliveries and six guard decisions (`VM_RESULT=PASS`); its 5,869-byte serial log SHA-256 is `bb31451fe036ef2e78788610d96c9293d25c8fb116c8181780379ca2ad279e6f`.

This local comparison supports reverse-path filtering as the failure mechanism. It does **not** establish the Ubuntu runner's original sysctl value. The later [hosted run 37408815046](https://github.com/dhtfish-98/VpnPeerPrefixBindingGate/actions/runs/37408815046) on revised commit `9790bd69767448b0a86be90599bb011170f20362` completed both jobs successfully. Its downloaded no-secret machine receipt reports `PASS`, nine exact receiver deliveries, six guard decisions, all six checks true, and required reverse-path-filter markers exactly once. The artifact ZIP SHA-256 `fadc935de1331a0754cbb7dfcf9c77d487686de866af3375d50692f3efc6d5c1` matches the GitHub API digest. This supports the fixture correction on hosted Ubuntu; the initial runner's original sysctl value remains unobserved. The intentionally weak gateway and upstream WireGuard rights boundary remain unchanged.
